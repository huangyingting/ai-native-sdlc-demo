## 三类核心演示场景

- **业务交付主线**：以“工单负责人”和“数据库就绪检查”为代表，贯穿业务决策、文档审批、Coding Agent 编码实现、CI 持续集成、镜像独立验证与人工现场验收的全生命周期。
- **运行保障演练**：以“发布可靠性”为代表，验证基于确定性策略的准入控制与自动回滚恢复机制。
- **受控工程实验**：涵盖代理人影响分析、故障诊断与 Agent 策略对比，通过独立测试套件客观评估模型给出的分析方案与候选代码。

## Copilot 与验证程序的职责边界

- **Coding Agent**：负责实现经审查批准的功能规格，提交代码变更 PR。
- **Copilot CLI**：负责生成结构化的分析方案与候选代码文本。在实验设计中，模型可用工具数与工具调用请求数严格限制为零。
- **GitHub Actions 与验证程序**：负责执行自动化测试、应用白名单候选代码并在受限 Docker 容器中执行独立检查，杜绝让模型“自评自审”。
- **交付审查机制**：规格说明（Spec）、实施计划（Plan）、测试用例与功能代码实行分阶段独立审批，最终交付产物由人工明确验收。

## 两条真实的执行链路

```text
业务交付主线：
  业务决策与人工审批 → Coding Agent 提交实现 PR
    → Actions 门禁检查 → 实际构建发布镜像 → 用户明确确认验收

受控工程实验：
  固定标准输入 → Copilot CLI 生成方案／诊断／候选文本
    → 白名单校验适配器 → Docker 测试套件与独立检查
    → 实测客观指标与代码差异证据
```

工程实验应用的基线代码特意保持未修改状态。候选代码在隔离实验中通过验证，并不意味着该代理人功能已经合并或部署到了服务台应用中。

## 查验证据的核心要素

查验 CLI 实验证据时，应重点核对以下 4 项核心要素：

1. **输入上下文**：固定的用户提示词，以及实际提供给模型的故障现场或基线代码。
2. **模型原始输出**：模型生成的推理理由与分类标签。
3. **候选代码差异**：模型提出的补丁代码中经人工审查确认的 Diff 摘录。
4. **独立验证结果**：文件修改范围、既有测试回归情况、独立行为检查与分类门禁通过状态。

## 结论边界与客观约束

- 可靠性演练基于预设策略的自动化脚本运行，而非由 Copilot 自主决策触发回滚。
- 模型即使能够正确推导配置故障的原因，也不一定会给出正确的 `classification` 枚举标签。
- 行为功能测试绿灯不代表实验完全达标；本实验如实记录并保留了 2 次分类标签未通过的原始结果。
- 在小样本集上的单次测试，不足以在统计学意义上证明某一 Agent 策略具备普适优势。
- 离线功能验收与隔离实验结果不构成生产环境安全认证。
